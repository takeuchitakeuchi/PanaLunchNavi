# 📋 企画書修正提案

## 🔴 重要な修正点

### 1. セクション番号の不整合
**問題**: セクション5の後にセクション7が続いており、セクション6が欠落している

**修正案**: 
- セクション5「テスト」の後にセクション6を追加（例：「6. デプロイ・環境構築」）
- または「7. 運用・保守・改善」を「6. 運用・保守・改善」に変更

### 2. テストセクションのテーブルフォーマット
**問題**: 154-160行のテーブルが正しくフォーマットされていない（パイプ区切りがない）

**修正案**: マークダウンテーブル形式に修正
```markdown
| テスト項目 | 内容 | 検証方法 |
|-----------|------|----------|
| T-001 | 店舗登録テスト | Streamlit上から投稿→Firestoreに保存されるか |
| T-002 | 検索テスト | キーワード・価格帯フィルターが動作するか |
...
```

### 3. 技術選定の整合性
**問題**: 
- Streamlitは単体でも実装可能なため、FastAPIの必要性が不明確
- VercelはStreamlitアプリを直接デプロイできない

**修正案**: 
- バックエンド: 「Python + FastAPI（オプション）」または「Streamlit単体（初期）→ FastAPI分離（拡張時）」と段階的に記載
- デプロイ: 「Streamlit Cloud or Heroku」に変更（Vercelを削除）

### 4. 日付の確認
**問題**: 2025/11/09は未来の日付（タイポの可能性）

**修正案**: 正しい日付に修正（2024/11/09？）

## 🟡 改善提案

### 5. データベース選定の段階的アプローチ
**提案**: 初期プロトタイプではJSONファイル、本番環境ではFirestoreという段階的アプローチを明記

**修正案**:
```
データベース | **段階的アプローチ** | 
- プロトタイプ: JSONファイル（`stores.json`）
- 本番環境: Firestore (NoSQL)
```

### 6. 認証方式の優先順位
**提案**: Google Workspace連携と簡易コード制限の実装順序を明確化

**修正案**:
```
認証 | **段階的実装** | 
- Phase 1: 簡易パスコード認証（開発・プロトタイプ用）
- Phase 2: Google Workspace連携（本番環境用）
```

### 7. セクション区切り文字の統一
**提案**: 「⸻」を「---」に統一して一貫性を保つ

### 8. API連携の説明の明確化

- Streamlit単体実装の場合は「Python関数呼び出し」に変更
- または「Phase 1: Streamlit単体 → Phase 2: REST API分離」と段階的に記載
