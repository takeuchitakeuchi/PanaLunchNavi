## 1. 技術スタック

### 1.1 共通技術スタック（Phase 1: プロトタイプ）

| カテゴリ | 技術 | バージョン | 用途 |
|---------|------|-----------|------|
| **フレームワーク** | Streamlit | 最新版 | Webアプリケーション開発 |
| **言語** | Python | 3.8以上 | バックエンド・フロントエンド統合開発 |
| **データストレージ** | JSONファイル | - | 店舗情報の永続化 |
| **デプロイ環境** | Streamlit Cloud | - | アプリケーションのホスティング |
| **バージョン管理** | GitHub | - | コード管理・デプロイ連携 |
| **開発環境** | VSCode | 最新版 | コードエディタ |

### 1.2 開発ツール

- **Python標準ライブラリ**: `json`, `datetime`, `random`
- **Streamlit**: UIコンポーネント、データ表示
- **Git**: バージョン管理（デプロイ時のみ使用）

- 認証機能なし（ユーザー名は自由入力）
- データベースなし（JSONファイルでのデータ管理）
- ローカル開発優先（デプロイ時のみGitHub使用）

## 3. 要件定義書

### 3.1 機能要件

| 機能ID | 機能名 | 優先度 | 概要 |
|--------|--------|--------|------|
| F-001 | 店舗リスト表示 | 高 | 登録済みランチ店を一覧で表示 |
| F-002 | 店舗詳細表示 | 高 | 店舗写真、メニュー、コメントを表示 |
| F-003 | 投稿フォーム | 高 | 新しいお店情報を投稿 |
| F-004 | 検索／フィルター | 中 | 価格帯・距離・ジャンルで検索 |
| F-005 | 評価・コメント | 中 | 星評価とレビューを登録 |

### 3.2 非機能要件

| 要件 | 内容 |
|------|------|
| **パフォーマンス** | 店舗リストの表示は3秒以内 |
| **可用性** | Streamlit Cloud上で24時間稼働 |
| **ユーザビリティ** | Streamlit標準UIを使用し、直感的に操作可能 |
| **保守性** | コードは読みやすく、関数単位で分割 |
| **拡張性** | Phase 2でFirestoreへの移行を考慮 |

### 3.3 データ要件

- **データ形式**: JSON形式
- **データ保存場所**: `stores.json`ファイル
- **データ構造**: 店舗情報、レビュー情報を含む
- **ユーザー情報**: メールアドレスまたは表示名（自由入力）

## 4. 方式定義書

### 4.1 システム構成

```
[ユーザー] → [Streamlitアプリ] → [JSONファイル]
                ↓
          [Streamlit Cloud]
```

### 4.2 データフロー

1. **データ読み込み**: `load_stores()`関数でJSONファイルから読み込み
2. **データ表示**: StreamlitのUIコンポーネントで表示
3. **データ入力**: フォームからユーザー入力を受け取る
4. **データ保存**: `save_stores()`関数でJSONファイルに保存

### 4.3 ファイル構成

```
プロジェクトルート/
├── app.py                 # メインアプリケーション
├── stores.json            # 店舗データ
├── requirements.txt       # Pythonパッケージ一覧
└── README.md             # プロジェクト説明
```

### 4.4 関数設計

| 関数名 | 入力 | 出力 | 処理内容 |
|--------|------|------|----------|
| `load_stores()` | - | 店舗データ（dict） | JSONファイルからデータを読み込む |
| `save_stores(stores)` | 店舗データ（dict） | - | JSONファイルにデータを保存 |
| `filter_stores(stores, keyword)` | 店舗データ、キーワード | フィルタ済みデータ | キーワードで店舗を検索 |
| `add_store(store_data, user_name)` | 店舗データ、ユーザー名 | - | 新しい店舗を追加 |
| `add_review(store_id, review, user_name)` | 店舗ID、レビュー、ユーザー名 | - | レビューを追加 |

### 4.5 データモデル

```json
{
  "stores": [
    {
      "id": "store001",
      "name": "店舗名",
      "genre": "ジャンル",
      "price": 価格,
      "location": "場所",
      "rating": 評価平均,
      "reviews": [
        {
          "user": "ユーザー名",
          "rating": 評価,
          "comment": "コメント",
          "date": "日付"
        }
      ],
      "posted_by": "投稿者名",
      "posted_date": "投稿日"
    }
  ]
}
```

### 4.6 UI設計

- **Sidebar**: 検索・フィルター機能
- **Main Area**: 店舗一覧（カード形式）
- **Detail Area**: 店舗詳細情報
- **Footer**: 投稿ボタン

## 5. テスト方針

### 5.1 テスト種類

| テスト種類 | 対象 | 実施タイミング |
|-----------|------|---------------|
| **単体テスト** | 各関数 | 実装時 |
| **結合テスト** | 機能連携 | 機能実装後 |
| **システムテスト** | 全体機能 | 全機能実装後 |
| **ユーザビリティテスト** | UI/UX | デプロイ後 |

### 5.2 テスト項目

| テストID | テスト項目 | 検証内容 | 期待結果 |
|---------|-----------|----------|----------|
| T-001 | 店舗登録テスト | 投稿フォームから店舗情報を登録 | JSONファイルに正しく保存される |
| T-002 | 検索テスト | キーワード・フィルターで検索 | 該当店舗が正しく表示される |
| T-003 | 詳細表示テスト | 店舗詳細情報を表示 | 店舗情報が正しく表示される |
| T-004 | UI表示テスト | レイアウトの確認 | レイアウトが崩れていない |
| T-005 | レビュー投稿テスト | レビューを投稿 | レビューが正しく保存・表示される |
| T-006 | ユーザー名入力テスト | ユーザー名を入力 | ユーザー名が正しく保存・表示される |

### 5.3 テスト実施方法

1. **手動テスト**: Streamlitアプリ上で各機能を手動で操作
2. **データ確認**: JSONファイルの内容を直接確認
3. **ブラウザテスト**: 複数のブラウザで表示確認

### 5.4 テスト環境

- **開発環境**: ローカル環境（`streamlit run app.py`）
- **本番環境**: Streamlit Cloud

### 5.5 バグ管理

- バグ発見時は即座に修正
- 重大なバグは次のタイムブロックで優先対応
- バグ修正後は再テストを実施
