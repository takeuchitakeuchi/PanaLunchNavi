## 📝 2. 企画・要件定義

### 🔍 市場調査
- 社員は基本的に社内の食堂を利用しているが、外部のランチ店に食べに行くこともある。
- 外部のランチ情報は社内のイントラネットで共有されていない。
- 食べログなどのアプリは使っているが、混雑具合まではわからない。
- 具体的なペインポイントは現時点では明確ではないが、まず基本的なお店の情報を示してくれるアプリを作成し、顧客インタビューを通じて改善していくことを目指す。

**用語解説**：
- **Webアプリ**: インターネットブラウザ（Chrome、Safariなど）で動作するアプリケーション
- **イントラネット**: 社内のみで利用できるネットワーク
- **ペインポイント**: ユーザーが抱えている課題や不便に感じている点
- **顧客インタビュー**: ユーザーに直接話を聞いて、ニーズや改善点を把握する手法

#### 📖 技術解説

**Streamlit（ストリームリット）**
- **説明**: PythonだけでWebアプリを作れるフレームワーク。HTMLやCSSの知識がなくてもUIを作成可能
- **メリット**: 学習コストが低い、開発スピードが速い、プロトタイプに最適
- **例**: `st.button("クリック")` と書くだけでボタンが表示される

**JSONファイル**
- **説明**: データをテキストファイル（.json）に保存する方法
- **メリット**: データベースのセットアップが不要、ローカルで動作確認が簡単
- **例**: `stores.json` というファイルに店舗情報を保存

**GitHub（ギットハブ）**
- **説明**: コードをクラウド上で管理するサービス。変更履歴を記録し、チームで共有可能
- **メリット**: コードのバックアップ、変更履歴の確認、Streamlit Cloudへのデプロイ時に必要
- **基本的な使い方**: `git add` → `git commit` → `git push` でコードをアップロード
- **注意**: Phase 1では開発は主にローカルで行い、デプロイ時のみGitHubを使用

**デプロイ**
- **説明**: 作ったアプリをインターネット上に公開すること
- **Streamlit Cloud**: Streamlitが提供する無料のホスティングサービス。GitHubにコードをプッシュするだけで自動的にアプリが公開される

**フロントエンド / バックエンド**
- **フロントエンド**: ユーザーが見る画面（ボタン、フォーム、リストなど）
- **バックエンド**: データの処理や保存を行う部分
- **Streamlitの特徴**: フロントエンドとバックエンドを1つのPythonファイルで書ける

**ペアプログラミング（バイブコーディング）**
- **説明**: 二人で一緒にコードを書く開発手法。一人がコードを書き、もう一人がレビューや提案を行う
- **メリット**: 知識の共有、バグの早期発見、学習効率の向上
- **Vibe Coding**: 楽しく、リラックスした雰囲気でコーディングすること

**VSCode（ブイエスコード）**
- **説明**: Microsoftが開発した無料のコードエディタ。Python開発に最適
- **メリット**: コード補完、エラー表示、デバッグ機能が充実
- **拡張機能**: Python用の拡張機能をインストールすると、さらに便利に

## 💻 4. 開発（Streamlit単体開発）

### Streamlitの実装方法

#### 📋 基本構造
```python
import streamlit as st
import json

# ページのタイトル
st.title("🍱 Panasonic Lunch Navi")

# データの読み込み（JSONファイルから）
def load_stores():
    with open('stores.json', 'r', encoding='utf-8') as f:
        return json.load(f)

# データの保存（JSONファイルに）
def save_stores(stores):
    with open('stores.json', 'w', encoding='utf-8') as f:
        json.dump(stores, f, ensure_ascii=False, indent=2)
```

#### 🎨 UIコンポーネント（実装方針）
| 機能 | Streamlitのコード | 説明 |
|------|------------------|------|
| 店舗リスト表示 | `st.dataframe(stores)` または `st.columns()` | データをテーブルまたはカード形式で表示 |
| 検索ボックス | `st.text_input("店舗名で検索")` | ユーザーが文字を入力できるテキストボックス |
| フィルター | `st.selectbox("ジャンル", ["和食", "洋食", "中華"])` | プルダウンメニューで選択 |
| 投稿フォーム | `st.form("新規店舗登録")` | フォーム内に複数の入力欄を配置 |
| ユーザー名入力 | `st.text_input("ユーザー名（メールアドレスまたは表示名）")` | 投稿・レビュー時にユーザー名を自由入力 |
| 評価スライダー | `st.slider("評価", 1, 5, 3)` | 1〜5の星評価をスライダーで選択 |
| コメント入力 | `st.text_area("コメント")` | 複数行のテキストを入力可能 |
| ボタン | `st.button("登録")` | クリックで処理を実行 |

#### 🔧 Python関数の役割
| 関数名 | 機能 | 説明 |
|--------|------|------|
| `load_stores()` | データ読み込み | JSONファイルから店舗データを読み込む |
| `save_stores(stores)` | データ保存 | 店舗データをJSONファイルに保存 |
| `filter_stores(stores, keyword)` | 検索処理 | キーワードで店舗を検索する |
| `add_store(store_data, user_name)` | 店舗追加 | 新しい店舗をデータに追加（ユーザー名を含む） |
| `add_review(store_id, review, user_name)` | レビュー追加 | 店舗にレビューを追加（ユーザー名を含む） |

**用語解説**：
- **関数**: 特定の処理をまとめたコードの塊。`def 関数名():` で定義
- **JSONファイル**: データを保存するテキストファイル。Pythonの`json`モジュールで読み書き可能
- **エンコーディング**: 文字コードの指定。日本語を使う場合は`encoding='utf-8'`が必要

### 📊 データモデル（JSONファイル形式）

#### ファイル構造
- `stores.json`: 店舗情報を保存

#### データ構造例（stores.json）
```json
{
  "stores": [
    {
      "id": "store001",
      "name": "Cafe Osaka",
      "genre": "和食",
      "price": 900,
      "location": "大阪本社から徒歩5分",
      "rating": 4.2,
      "reviews": [
        {
          "user": "y.yun@panasonic.com",
          "rating": 5,
          "comment": "美味しい！",
          "date": "2024-11-09"
        },
        {
          "user": "田中太郎",
          "rating": 4,
          "comment": "安くて良い",
          "date": "2024-11-08"
        }
      ],
      "posted_by": "y.yun@panasonic.com",
      "posted_date": "2024-11-09"
    }
  ]
}
```

**用語解説**：
- **JSON**: JavaScript Object Notationの略。データを構造化して保存する形式
- **配列（リスト）**: `[]`で囲まれた複数のデータ。例：`[1, 2, 3]`
- **オブジェクト（辞書）**: `{}`で囲まれたキーと値のペア。例：`{"name": "カフェ", "price": 900}`
- **ユーザー名**: メールアドレス（例：`y.yun@panasonic.com`）または表示名（例：`田中太郎`）を自由に入力可能
